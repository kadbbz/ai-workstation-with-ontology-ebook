# 基于本体论的 AI 工作台

## 封面导读

一个采购主管拿着手机上的通用 AI 工具分析供应商报价，顺手提出了下一步：能不能直接查 ERP、看库存、生成补货方案？业务方看到的是一名可以理解目标、自己安排步骤的数字员工；IT 部门看到的是身份、数据口径、权限、审计和回滚。两边都没有错，缺的是一层能把自然语言目标翻译成受控业务动作的工程结构。

这本小册子沿着这个问题展开。前四篇说明企业 AI 为什么会出现“结果错”和“过程不可控”；接着区分 MCP、RAG、微调和本体各自负责的层次；再从实体、属性、动作、关系和策略进入 Agent Loop、Workflow、MQTT、多用户上下文和四层工作台；最后落到活字格应用接入、元数据治理、自动化测试、白名单交付、网络安全和项目立项。

文中的开发场景均为假设场景，或明确标注为当前项目样本。行业标准、论文和产品规范用正文链接给出，样本观察不替代企业自己的任务回归、权限测试和上线审查。

正文中原先标出的行业共识边界已经按改进方向回写；涉及具体产品、身份体系和安全评审的判断仍应以实际环境核验，详见[行业共识改进方向（已执行）](<待确认-行业共识改进方向.md>)。
